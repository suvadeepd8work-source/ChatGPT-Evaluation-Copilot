# Trust Analysis: Heuristics & Barriers

## 1. Trust Triggers (What builds trust?)
| Trigger | Description | User Evidence |
| :--- | :--- | :--- |
| **Fluency & Clarity** | Well-structured, logical-sounding sentences. | Soumya, Suvamita, Riya |
| **Citations** | Inclusion of references (even if not verified). | Shwetlana, Neha |
| **Alignment** | Matching the user's existing knowledge. | Navarup, Soumya |
| **Structural Nuance** | Showing multiple perspectives or admitting limits. | Sanchita |
| **Deep Analysis** | Providing "deep dig" style explanations. | Subhojyoti, Debapriya |

## 2. Trust Barriers (What destroys trust?)
- **Discovered Inaccuracy**: Finding a mistake after the fact (Soumya, Navarup, Suvamita).
- **Generic Responses**: Answers that feel "too safe" or just echo the user.
- **Hidden Logic**: Not being able to see *how* the AI reached a conclusion.
- **Outdated Data**: Technical or factual info that doesn't reflect the current state.

## 3. The "Confidence" Paradox
Interview results show a split in how "Confidence" is perceived:
- **Novice/Student View**: Confidence = Trustworthiness. "If it sounds professional, I trust it." (Riya).
- **Expert/Professional View**: Confidence = Red Flag. "I usually ignore overly confident wording and focus on actual accuracy." (Navarup, Subhojyoti).

## 4. Trust Calibration Requirement
The system must move users from **Blind Trust** (Riya) to **Conditional Trust** (Arjun/Neha) by exposing the "Certainty" of the AI versus the "Evidence" available.
